# how-to-git

## Как начать работу с git/github

1. Создаем аккаунт на GitHub, добавляемся ко мне в команду (я приглашу, нужно будет просто присоединиться по ссылке из сообщения)
2. Скачиваем утилиту git на систему. `sudo apt install git` (для Debian/Ubuntu)
3. Создаем ssh ключ: `ssh-keygen -t ed25519 -C "почтаотгитхаба@example.com"`
4. Достаем Public Key: `cat ~/.ssh/id_ed25519.pub`. Копируем, заходим на GitHub, добавляем его в настройках, в разделе SSH keys.
5. Добавляем данные в git: 
	`git config --global user.name "Имя пользователя"`
	`git config --global user.email "Почта от гитхаба"`
6. Проверка подключения: `ssh -T git@github.com` (Должно появиться приветствие с вашим никнеймом)

На этом первоначальная настройка заканчивается. Дальше у вас два варианта пути в команде:
	1 - Создать свой репозиторий
	2 - Продолжить работу в уже созданном репозитории

Разберем оба варианта:

## 1 - Создание репозитория

1. Создаем рабочую директорию на своей системе: 
	`mkdir -p название && cd название`
2. Инициализируем репозиторий: 
	`git init`
3. Переименовываем ветку в main (Стандартное имя для главной ветки): 
	`git branch -M main`
4. Связываем репозиторий на вашей системе с репозиторием на GitHub:
	`git remote add origin git@github.com:devops-study-mirea/названиерепозитория.git`
5. Делаем пустой коммит и пуш для создания ветки main:
	`touch README.md`
	`git add .`
	`git commit -m "Initial commit"`
	`git push -u origin main`



## 2 - Продолжить работу в уже созданном репозитории

1. Копируем к себе репозиторий: `git clone git@github.com:devops-study-mirea/repo.git`
Дальнейших действий не требуется, все связывается автоматически.

Поздравляю!!! На этом этапе вы связали git с github, создали/скопировали репозиторий. Дальнейшие инструкции связаны с работой в репозиториях.

## Правильная работа с ветками, push и pull

1. Берем последнюю версию репозитория, пока находимся в ветке main:
	`git pull --rebase`
	Должно высветиться "Already up to date." либо должны докачаться какие-то файлы.

2. Создаем отдельную ветку и переключаемся на нее. В main ветке работать нельзя, в особенности в команде.
	`git switch -c названиеветки`

Важно отметить, что название лучше всего писать так:
	feature/какаяфича
	fix/какойфикс
Например: для этого файла у меня была создана ветка feature/README, так как я работаю в этой ветке над README.md файлом. Для каждой задачи создаем отдельную ветку.

3. Создаем/копируем в нашу директорию какой-нибудь файл: например, `touch file.txt`.
4. Делаем коммит с изменениями:
	`git add file.txt` (добавляем нужные файлы в коммит, точка вместо названия файла добавит все изменения в директории)
	`git commit -m "Created file file.txt"`
	Важно: Комментарий коммита должен содержать что мы добавили или исправили. Коммиты должны быть атомарными (маленькое количество изменений. чем больше коммитов - тем лучше)
5. После того как мы сделали все нужные нам коммиты, убеждаемся что мы находимся НЕ в ветке main, можем запушить наши изменения:
	`git push -u origin названиеветки`
	Либо: `git push -u origin HEAD` - автоматически подставится название ветки, в которой вы сейчас находитесь.
6. После этого заходим в GitHub, увидим там pull request (Запрос слияния нашей ветки с веткой main). На этом этапе обычно находится проверка кода, синтаксиса итд. Пока что можно просто смёржить наш request.

На этом все, ниже простой алгоритм для последующей работы.
1. Перед началом работы всегда `git pull`, находясь в main.
2. Работаем над новой задачей? Создаем отдельную ветку.
3. Сделали изменения в файле? Добавляем наши изменения через `git add`, делаем коммит с описанием того, что сделали.
4. Сделали достаточно коммитов? Проверяем что мы не в ветке main, делаем `git push`, подтверждаем слияние на GitHub.

Данный файл будет обновляться в дальнейшем по мере нашего обучения.
